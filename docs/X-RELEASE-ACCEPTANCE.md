# X / Twitter 适配与上线验收

适用包为 Android `com.twitter.android`。网页 `x.com` 的浏览器播放不属于本模块作用域。每个新的 X APK 版本、模块 APK 或框架变更都需要重新验收；旧版本的日志不能证明当前版本可用。

## 只读设备预检

在 PowerShell 7 中指定目标序列号，避免连错设备：

```powershell
./scripts/Test-XDevicePreflight.ps1 -Serial '<adb serial>' -ExpectedModel PJZ110 -OutputPath ./LogBugFix/x-preflight.json
```

输出 `PREFLIGHT_OK` 只表示目标身份、开机和安装信息已读到，不表示倍速生效。`unauthorized` 时先在手机允许 USB 调试；不删除 ADB 密钥、不清除应用数据。配置查询来自 shell UID，仍需确认 X 注入进程实际读取的值。诊断 JSON、APK、截图和完整日志放入被 Git 忽略的本地目录，不提交个人账号或信息流内容。

手机已向 ADB shell 开放 root、且使用 `/data/adb/lspd/log/modules_*.log` 日志出口时，可加 `-CollectHookEvidence`。只保留当前 X 主进程 PID 的 VideoSpeed 行，分别报告 Hook 注册与设速调用是否出现；无日志或 root 不可用不等于 Hook 失败，仍需按框架实际出口排查。PID 可能复用，必须核对时间窗口。

## 发布门禁

所有必验项通过，才能将该设备/版本标为可上线；缺项为待验，失败为不通过。

| 层级 | 必验项 | 通过标准 / 证据 |
|---|---|---|
| 身份 | 手机、系统、X、框架、模块 | 记录精确版本、构建、模块 APK SHA256 和签名证书指纹；安装后回读版本与更新时刻 |
| 作用域 | 模块启用与 X 勾选 | LSPosed / Vector 当前作用域可见；冷启动当前 X 主进程出现模块加载日志 |
| 适配 | 实际播放器映射 | 当前 APK 类/方法签名与 Hook 注册一致；没有未找到方法或调用异常；不能仅凭类名相同宣称兼容 |
| 配置 | 两个非 1.0 默认值 | 设置页分别保存 1.5、2.0，X 进程在新的视频上读取对应配置并触发对应设速 |
| 播放 | 真实视频速度 | 同一可重复 VOD 的连续 10 秒墙钟区间，媒体进度增量与目标速度相符（误差 ≤15%）；排除卡顿、暂停、拖动、循环和广告，至少重复两次 |
| 生命周期 | 重进与切片 | 冷启动、连续切换至少 3 个视频、前后台切换、全屏进入/退出均保留预期倍速；播放与声音正常 |
| 手动设置 | 用户临时倍速 | 播放中手动选另一速度后该视频不立即被模块覆盖；切到下一视频恢复模块默认值；含手动 1.0 |
| 关闭 | 默认值 1.0 / 模块禁用 | 分别测试配置 1.0 和禁用 X 作用域后冷启动；实际恢复原生播放，没有继续注入 |
| 稳定性 | 异常与影响范围 | 10 分钟使用无本次引入的 crash/ANR、递归异常或持续日志洪泛；如改共享逻辑，复测原有微信路径 |
| 工程 | 构建与发布包 | assembleDebug、lintDebug 通过；发布候选 assembleRelease 通过、稳定签名与已发布包一致、覆盖安装保留配置，再复跑上述真机项 |

日志必须来自本轮冷启动的时间窗口和当前进程。`hooked ...` 只证明注册，`prepare -> ...` 只证明调用未抛异常，二者都不能代替媒体进度或用户实际播放验收。无法得到进度时可使用明确记录的人工播放验证，但计时项仍标待验，不给完整上线通过结论。

## 修复与回退

先分清作用域未启用、配置不可读、播放器类延迟加载、混淆映射漂移和实际播放被覆盖，再改对应层。映射漂移时只从当前设备拉取 APK 到忽略目录，检查 DEX 的播放器、参数字段、setter 与 prepare 签名；不对所有含 float 的方法做盲目 Hook。

安装前保留原 APK/签名与配置值；签名不一致时停止覆盖安装，不通过卸载绕过。失败优先取消 X 作用域并重启 X，或覆盖安装同签名旧 APK；不得清除 X 数据。验收后恢复用户原有默认速度及作用域，记录实际恢复值。

## 本轮状态（2026-10-12）

设备预检已通过：OnePlus 13 `PJZ110`，Android 16，构建 `PJZ110_16.0.1.303(CN01)`；X `12.28.0-prod.01 (312280001)`；VideoSpeed `1.2.10 (1002010)`；Vector `v2.2 (3080-88f8e1fa-JingMatrix-Vector)`；shell 配置查询为 `1.75`。

12:31:11 冷启动的 X 主进程日志确认模块加载、`androidx.media3.exoplayer.d0.b` prepare 和 `d0.c` 播放参数 Hook 注册成功，attach 重试未重复注册。

13:01～13:07 获得手机占用授权后完成播放页测试：

| 项目 | 实测 | 结果 |
|---|---|---|
| 自动倍速 | 同一 VOD，13:04:37～13:04:48 两次截图相隔 10.6765 秒；剩余时间 6:06 → 5:47，媒体前进 19 秒，约 1.78x | 与 1.75x 配置相符；一次计时样本通过 |
| 按钮显示 | 上述播放期间按钮始终为 1x | 未反映模块注入的实际速度 |
| 手动 1.25x | 点击后按钮为 1.25x，日志记录 requested=1.25；10.7032 秒内剩余时间 2:22 → 2:08，约 1.31x | 在秒级显示误差内符合 1.25x，实际生效 |
| 手动 1.5x / 2x | 点击后分别出现 requested=1.5 / 2.0，模块未替换这些请求 | setter 请求保留；未单独计时 |
| 手动回到 1x | 循环点击回到 1x，日志再次出现两次 `setPlaybackSpeed 1.0 -> 1.75` | 失败：被模块按自动重置处理 |

根因可在 `MainHook.handleTwitterSetPlaybackParameters` / `handleTwitterSetPlaybackSpeed` 复核：两者按入参是否为 1.0 判断自动重置，没有当前视频的手动选择状态。低层播放器参数替换没有同步 X 上层速度按钮状态，故显示与实际速度分离。直接把 1x 文字换成 1.75x 会掩盖状态问题，也不能让用户手动 1x 生效。

机主明确选择现有自动功能优先，仅在容易实现且不破坏现有功能时调整显示与临时速度。本轮未定位到可小改并验证的 X 界面状态入口，因此**保留 1.2.10 播放器实现及原配置 1.75x**，不安装实验 APK。将来修复应识别明确的速度按钮事件，为当前视频保留手动速度（含 1x），换片后恢复默认，并让显示读取实际播放状态；不能以所有触摸或所有非 1x 请求推断手动动作。

当前结论：**自动倍速实际生效；手动非 1x 有效；显示与临时 1x 存在已复现限制，完整上线门禁未通过**。重复计时、两组默认配置、模块关闭、全部生命周期、10 分钟稳定性及稳定签名 Release 验收仍未完成。原始截图、计时 JSON 和 APK 仅在忽略目录 `LogBugFix/` 留存，不提交个人信息流内容。
